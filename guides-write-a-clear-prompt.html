How to write a clear prompt

A practical five-part brief: task, context, audience, format and boundaries.

“Make this better” leaves most of the task undefined. Before writing a prompt, decide what the finished work should look like and which facts the tool may use.

1. Name the deliverable

Ask for something you can inspect: a five-page website brief, a 100-word product description or a debugging checklist. “Improve my business” is much harder to evaluate.

2. Give the useful context

Include the business type, existing situation, available material and any decisions already made. For a bakery website, explain whether it needs enquiries, a catalogue or connected payments. These are different requirements.

3. Identify the audience

A proposal for a business owner needs different language from implementation notes for a developer. State who will use the output and what they already know.

4. Choose an output format

Use a table when you need comparable options, a checklist when you need launch checks and finished copy when you need an email. The format should help you use the answer, rather than decorate it.

5. Set boundaries

List important exclusions and factual limits. If the budget or delivery date has not been agreed, say so. Ask the tool to identify missing information instead of inventing commercial details.

Create a five-page bakery website brief for the owner and developer. Include a cake catalogue and WhatsApp enquiries. The owner supplies photos and prices. Return a page list, content checklist and open questions. Do not invent a budget or a launch date.

Use the studio, then review it
